# Integración con Git

El botón **Git** de la barra de menús abre el control de versiones del proyecto. Maker Studio usa el ejecutable de Git instalado en tu ordenador. Si el proyecto aún no es un repositorio, puedes inicializarlo desde esta ventana.

## Cambios

La barra superior muestra el proyecto, la rama actual, el número de archivos modificados y los botones **Fetch (Buscar remotos)**, **Pull (Traer)** y **Push (Subir)**; pasa el ratón por el nombre del proyecto para ver su ruta completa. La pestaña **Changes (Cambios)** muestra a la izquierda los archivos del proyecto que Git detecta como modificados, con el mensaje y el botón de commit fijos abajo, y a la derecha la vista previa del archivo seleccionado. Selecciona cuáles incluir, escribe un mensaje y crea el commit. Maker Studio incluye los archivos guardados en disco, así que guarda primero los cambios del editor; las ediciones sin guardar bloquean las acciones de Git que podrían sobrescribirlas.

Usa **Select All (Seleccionar todo)** y **Deselect All (Deseleccionar todo)** sobre la lista para cambiar la selección de una vez. Puedes descartar los cambios de los archivos seleccionados con el botón de papelera sobre la lista, o de un archivo desde su menú contextual. Los archivos versionados vuelven a su último commit; los archivos nuevos seleccionados se eliminan. El editor vuelve a cargar los datos afectados cuando es posible. Si no puede recargar un cambio de forma segura, te pedirá que vuelvas a abrir el proyecto.

Los archivos de texto muestran cuántas líneas se añadieron y eliminaron (**+N −M**) en las dos listas de archivos y en el encabezado de la vista previa; los archivos binarios y los archivos nuevos sin seguimiento no tienen recuento. Arrastra la barra entre la lista de archivos y la vista previa para ensanchar o estrechar la lista, o enfócala y usa ←/→ (mantén Shift para pasos más grandes). El ancho se aplica a las dos pestañas hasta que cierres el diálogo.

## Historial de commits

Abre **Commit history (Historial de commits)** para ver en un grafo los commits de las ramas y referencias del repositorio. Cada fila muestra el asunto del commit, sus etiquetas de rama o referencia, autor, fecha y hash corto. Los commits aparecen primero con la fecha de autor más reciente siempre que lo permitan las relaciones entre ellos. Junto al título aparece un indicador mientras se carga una página. El grafo carga los primeros 100 commits y después carga automáticamente otros 100 al llegar al final de la lista, hasta un máximo de 1.000. Al alcanzar el límite, un aviso indica que se muestran los 1.000 commits más recientes.

Al abrir la pestaña, se selecciona el commit de la rama actual si está entre los commits cargados; si no, se selecciona el primero.

Con el diálogo ancho, el grafo queda arriba y la lista de **Changed files (Archivos modificados)** y la vista previa aparecen en paralelo debajo. Las filas compactas alinean en columnas el grafo, el asunto y las referencias, el autor, la fecha y el hash para mostrar más historial. Arrastra los separadores entre columnas para cambiar su ancho o enfoca uno y pulsa **← / →** (mantén **Shift** para un ajuste mayor). La columna del grafo se puede estrechar hasta 40 px; los anchos mínimos mantienen legibles el asunto, el autor, la fecha y el hash. Al estrechar el diálogo, el grafo, la lista y la vista previa se apilan en vertical; cada panel tiene su propio desplazamiento y el diálogo no añade una barra vertical. En el ancho mínimo se ocultan el autor y la fecha para dar sitio al asunto, las referencias y el hash.

Las fechas de los commits usan el formato **DD/MM/YYYY**. Arrastra el separador horizontal entre el grafo y los paneles inferiores para ajustar la altura del grafo entre el 20 % y el 80 % del espacio flexible (50 % por defecto); los paneles inferiores comparten el espacio restante y pueden ocupar hasta el 80 %. Ambas áreas cambian de tamaño mientras arrastras. También puedes enfocar el separador y pulsar **↑ / ↓** para cambiarlo en pasos del 5 %, o **Home / End** para ir a los límites.

Usa **↑ / ↓** para moverte por los commits y **Home / End** para saltar al primero o al último. Tab solo enfoca el commit activo del grafo.

Haz clic derecho en un commit (o enfócalo y pulsa la tecla Menú o **Shift+F10**) para copiar su ID, ID corto, asunto, descripción, mensaje completo, autor o fecha.

Selecciona un commit para ver sus archivos modificados y el estado de cada uno. La lista solo incluye archivos dentro de la carpeta del proyecto, aunque el repositorio de Git también contenga otros. Selecciona un archivo para comparar ese commit con su primer padre en la vista previa situada junto a la lista. El control **Styled / Raw text** solo aparece para JSON, XML y Markdown. Markdown en modo Styled se muestra renderizado como Markdown; JSON y XML mantienen el resaltado de sintaxis. Los demás lenguajes de código compatibles conservan siempre el resaltado y no muestran este control. El lenguaje se deduce de la extensión (las entradas de Scripts usan Ruby); el estilo no afecta a las marcas de cambios y se restablece al seleccionar otro archivo. Cuando existen las dos versiones, el encabezado también ofrece **Side by side (Lado a lado)** y **Unified (Unificado)**. El modo lado a lado muestra paneles alineados antes/después; el unificado intercala el contexto y los cambios en un solo panel. Los archivos de texto y las entradas de Scripts añadidos o eliminados muestran solo la versión existente; un archivo vacío existente se distingue de uno ausente. El resaltado admite Ruby, JavaScript/JSX, TypeScript/TSX, JSON, Markdown, CSS, HTML, XML, YAML, TOML, Python, shell y SQL; los demás textos se muestran sin resaltado. Scripts, registros de base de datos y mapas conservan sus vistas estructuradas; al seleccionar un mapa se dibujan enseguida sus versiones anterior y posterior lado a lado, ocupando casi toda la altura de la vista previa; las dos vistas se mueven siempre a la vez. Usa la rueda del ratón para desplazarte en vertical, **Shift+rueda** en horizontal, **Ctrl+rueda** para hacer zoom en el cursor, y mantén **Espacio** mientras arrastras (o arrastra con el botón central) para mover la vista. Usa la barra superior para acercar, ajustar o resaltar las casillas y los eventos modificados (estas opciones se mantienen al seleccionar otro mapa y la próxima vez que abras el diálogo), y el botón de tamaño completo del encabezado de cada lado para abrir ese mapa en el visor ampliado. Los detalles de casillas, eventos y propiedades aparecen debajo, en la sección plegada **Change details (Detalles del cambio)**.

Los archivos de imagen (PNG, JPEG, BMP, GIF y WebP) muestran una vista previa de ambos lados. Haz clic en una imagen para abrir un visor ampliado. Se abre ajustada a la ventana y usa los mismos controles que los mapas: rueda para desplazarte, **Shift+rueda** en horizontal, **Ctrl+rueda** para hacer zoom en el cursor y **Espacio+arrastrar** o arrastrar con el botón central para mover la vista. Los botones de la barra alejan, acercan y vuelven a **Fit (Ajustar)** la imagen. Ogg, MP3 y WAV usan controles con el estilo de la aplicación si el navegador admite el códec: reproducir/pausar, posición y duración con una barra de búsqueda, y volumen. MIDI tiene un botón equivalente para reproducir/detener. Cada lado tiene un límite de 16 MiB; los archivos multimedia más grandes no se pueden previsualizar. Si se añadió o eliminó un archivo, solo aparece el lado existente; los archivos multimedia modificados conservan la vista lado a lado.

## Ramas y remotos

Elige una rama local y cámbiala desde los controles de ramas. Para cambiar de rama el proyecto debe estar limpio: si hay archivos modificados o ediciones sin guardar, al elegir otra rama aparece un mensaje que indica qué hacer primero. Configura un remoto y una rama upstream en Git antes de usar Pull o Push.

**Fetch (Buscar remotos)** consulta los remotos configurados y actualiza los contadores de commits pendientes sin modificar los archivos del proyecto. Los contadores aparecen en **Pull** (commits por traer) y **Push** (commits por subir) y reflejan la última búsqueda; pulsa Fetch para consultar de nuevo. Con la búsqueda automática activada, la ventana se abre al instante y consulta el remoto en segundo plano mientras un pequeño indicador gira en la barra superior. Esta opción está desactivada por defecto. Al activarla en **Ajustes → Git**, Maker Studio consulta los remotos del proyecto abierto cada cinco minutos. Solo actualiza las referencias remotas de Git; Pull sigue siendo manual.

**Pull** necesita que todo el repositorio esté limpio. Usa el merge normal de Git sin guardar cambios automáticamente en otro sitio. El editor vuelve a abrir el proyecto solo si Pull modifica sus archivos.

### Resolver conflictos de fusión

Los archivos de datos de Maker Studio, como los mapas, son binarios, así que un archivo modificado por ti y también en el remoto no se puede fusionar línea a línea. Cuando Pull encuentra un conflicto así, la fusión queda abierta y la pestaña de cambios muestra el aviso **Merge in progress (Fusión en curso)** con el número de conflictos. Los archivos en conflicto aparecen primero. Selecciona uno para comparar **tu versión** con la **versión entrante** (los mapas se dibujan lado a lado como *El tuyo* y *Entrante*) y elige **Keep mine (Conservar el mío)** o **Use theirs (Usar el entrante)**. Cuando no quedan conflictos, **Complete merge (Completar fusión)** confirma la fusión y recarga el proyecto. **Abort merge (Cancelar fusión)** pide confirmación, devuelve todos los archivos a su estado anterior al Pull y recarga el proyecto. Mientras hay una fusión en curso se desactivan los commits normales, descartar, Pull, Push y el cambio de rama. Los conflictos fuera de la carpeta del proyecto, los enlaces simbólicos y los submódulos siguen cancelando la fusión y conservan tus commits locales; resuélvelos con otro cliente de Git. **Push** envía los commits locales al remoto configurado.
