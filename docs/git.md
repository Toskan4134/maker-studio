# Git Integration

The **Git** button in the menu bar opens project version control. Maker Studio uses the Git executable installed on your computer. If the project is not a repository yet, initialize it from this window.

## Changes

The toolbar at the top shows the project, the current branch, the number of changed files and the **Fetch**, **Pull** and **Push** buttons; hover the project name to see its full path. The Changes tab lists project files Git sees as changed on the left, with the commit message and **Commit selected files** pinned at the bottom, and the selected file's preview on the right. Select the files to include, enter a commit message, and commit them. Maker Studio commits files saved on disk, so save editor changes first; unsaved edits block Git actions that could overwrite them.

Use **Select All** and **Deselect All** above the list to change the selection in one step. You can discard changes for the selected files with the trash button above the list, or for one file from its right-click menu. Tracked files return to their last commit; selected untracked files are deleted. The editor reloads affected data when possible. If it cannot reload a change safely, it asks you to reopen the project.

Text files show how many lines were added and removed (**+N −M**) in both file lists and in the preview header; binary files and new untracked files have no count. Drag the bar between the file list and the preview to make the list wider or narrower, or focus it and use ←/→ (hold Shift for bigger steps). The width applies to both tabs until you close the dialog.

## Commit history

Open **Commit history** to see commits from the repository's branches and refs in a graph. Each row shows the commit subject, any branch or ref labels, author, date, and short hash. Commits appear newest first by displayed author date wherever their parent relationships allow. A spinner appears beside the heading while a page loads. The graph loads the first 100 commits, then automatically loads another page of 100 when you reach the end of the list, up to 1,000. At the limit, a notice says that the 1,000 most recent commits are shown.

When the tab opens, it selects the current branch's commit if it is in the loaded graph; otherwise, it selects the first loaded commit.

At a wide dialog size, the graph sits above the **Changed files** list and comparison preview, which appear side by side. Compact commit rows align the graph, subject and refs, author, date, and hash into columns, so more history fits in the graph. Drag a divider between columns to resize them, or focus it and press **← / →** (hold **Shift** for a larger step). The graph column can shrink to 40px; minimum widths keep the subject, author, date, and hash readable. As you make the dialog narrower, the graph, file list, and preview stack vertically; each panel scrolls independently without adding a scrollbar to the dialog. At the narrowest size, author and date give way to the commit subject, refs, and hash.

Commit dates use **DD/MM/YYYY**. Drag the horizontal divider between the graph and the lower panels to resize the graph from 20% to 80% of the flexible workspace area (50% by default); the lower file and preview panels share the remaining space and can occupy up to 80%. Both areas resize live as you drag. You can also focus the divider and press **↑ / ↓** to adjust it in 5% steps, or **Home / End** to jump to either limit.

Use **↑ / ↓** to move through commits and **Home / End** to jump to the first or last one. Tab focuses only the active commit in the graph.

Right-click a commit (or focus it and press the Menu key or **Shift+F10**) to copy its ID, short ID, subject, description, full message, author or date.

Select a commit to list its **Changed files**, including each file's status. The list is scoped to your project folder, even when the Git repository also contains other files. Select a file to compare that commit with its first parent using the preview beside the list. The **Styled / Raw text** control appears only for JSON, XML, and Markdown. Styled Markdown renders as Markdown; JSON and XML use syntax highlighting. Other supported code languages always keep syntax highlighting and do not show this toggle. The language is inferred from the file extension (Scripts entries use Ruby); style changes do not affect change marks and reset when you select another file. When both versions exist, the header also offers **Side by side** and **Unified**. Side by side shows aligned before/after panes; Unified shows context and changes interleaved in one pane. Added or deleted text files and Scripts entries show only the version that exists; an existing empty file is shown as empty rather than treated as missing. Syntax styling covers Ruby, JavaScript/JSX, TypeScript/TSX, JSON, Markdown, CSS, HTML, XML, YAML, TOML, Python, shell, and SQL; other text uses plain styling. Scripts, database records, and maps retain structured previews. Selecting a map draws the before and after versions side by side right away, using most of the preview height; both views always move together. Scroll the mouse wheel to move vertically, **Shift+wheel** to move sideways, **Ctrl+wheel** to zoom at the cursor, and hold **Space** while dragging (or drag with the middle button) to pan. Use the toolbar above them to zoom, fit, or highlight changed tiles and events (the highlight choices stay on when you select another map and the next time you open the dialog), and the full-size button in each side's heading to open that map in the large viewer. The tile, event, and property details are listed below the maps under a collapsed **Change details** section.

Image files (PNG, JPEG, BMP, GIF, WebP) show before/after previews. Click an image to open a larger viewer. It opens fitted to the window and uses the same controls as the maps: wheel to scroll, **Shift+wheel** to scroll sideways, **Ctrl+wheel** to zoom at the cursor, and **Space+drag** or middle-drag to pan. The toolbar buttons zoom out, zoom in, and **Fit** the image again. Ogg, MP3, and WAV use app-styled controls when the browser supports the codec: play/pause, elapsed and total time with a seek bar, and volume. MIDI has a matching Play/Stop action. Each side is limited to 16 MiB; larger media files cannot be previewed. Added or deleted media shows only the side that exists; modified media remains side by side.

## Branches and remotes

Choose a local branch and switch to it from the branch controls. Switching needs a clean project: if there are changed files or unsaved edits, choosing another branch shows a message saying what to do first. Configure a remote and upstream branch in Git before using Pull or Push.

**Fetch** checks the configured remotes and refreshes the counts shown on **Pull** (commits to bring in) and **Push** (commits to send) without changing project files. The counts show the result of the last fetch; use Fetch to check again. With automatic fetch enabled, the window opens at once and checks the remote in the background while a small spinner shows in the toolbar. This setting is off by default. When enabled under **Settings → Git**, Maker Studio checks the open project's remotes every five minutes. This only updates Git's remote references; Pull stays manual.

**Pull** requires the whole repository to be clean. It uses Git's normal merge behavior without auto-stashing. The editor reopens the project only when Pull changes its files.

### Resolving merge conflicts

Maker Studio data files such as maps are binary, so a file changed both by you and on the remote cannot be merged line by line. When Pull hits such a conflict, the merge stays open and the Changes tab shows a **Merge in progress** banner with the number of conflicts. Conflicted files are listed first. Select one to compare **your version** with the **incoming version** (maps are drawn side by side as *Yours* and *Incoming*), then choose **Keep mine** or **Use theirs** for it. When no conflicts remain, **Complete merge** commits the merge and reloads the project. **Abort merge** asks for confirmation, then returns every file to how it was before the pull and reloads the project. While a merge is in progress, normal commits, discards, Pull, Push and branch switching are disabled. Conflicts outside the project folder, symbolic links and submodules still abort the merge and keep your local commits; resolve those with another Git client. **Push** sends local commits to the configured remote.
